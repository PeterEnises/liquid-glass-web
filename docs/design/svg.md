# Плагин жидкого стекла: путь «SVG-фильтр + копия фона», без WebGL

Проект архитектуры. Составлен 30.10.2026 ночью, без кода и без замеров: это план, по которому писать и
мерить. Основа — отчёты из `research/*.md` (apple, audit, browsers, fresh, graphics, implementations,
performance) и `CONTEXT.md`, плюс добор источников этой ночью (ссылки в конце).

Метки:
- **[S27]** — проверено в настоящем Safari 27 на macOS (факты из `CONTEXT.md`);
- **[Chrome]** — измерено нами в Chrome (аудит, `research/tools/audit-*.mjs`);
- **[ист.]** — по источникам, нами не проверено;
- **[гипотеза]** — наш вывод или идея. В настоящем Safari не проверено, требует A/B-проверки;
- **[оценка]** — прикидка по формуле из раздела 10, не замер.

Всё про Safari и iPhone без метки [S27] **требует проверки в настоящем Safari**. Playwright-WebKit
доказательством не считаем.

## 0. Коротко

1. **Угол этого проекта:** взять от SVG-фильтров всё, что они могут дать в каждом браузере, и ни в одном
   браузере не ломаться. WebGL не используем совсем. Это и самостоятельный вариант, и запасной путь для
   WebGL-варианта: те же уровни, тот же API.
2. **Пять уровней (L0–L4)** вместо «жидкое / матовое». Уровень выбирается по трём осям: *что умеет
   движок*, *откуда взять картинку за стеклом*, *что сейчас происходит* (покой, медленная или быстрая
   прокрутка, смена слайда). Плюс **регулятор кадров**: если уровень не держит бюджет кадра, плагин
   сам спускается на ступень ниже.
3. **Главная новая идея для Safari и iPhone — «жидкое в покое» (L2).** Пока страница стоит, фильтр
   посчитан один раз и Safari держит результат в слое [S27: кэш фильтра]. Во время прокрутки и смены
   слайда показываем матовое стекло на видеокарте, а по `scrollend` возвращаем жидкое. Процессорный
   фильтр тогда считается раз в остановку, а не 60 раз в секунду. На iPhone это единственный способ
   показать честное преломление без WebGL [гипотеза].
4. **Дорогое в фильтре урезаем в 3–4 раза** [оценка]: область фильтра по размеру кромки, а не «+20 %
   и +50 %»; один проход смещения вместо трёх в Safari и Firefox; без `feComposite arithmetic`;
   размытие и насыщенность запекаются в копию при сборке.
5. **Всё, что не преломление, — CSS вне фильтра:** блик, светлая кромка, тон, тень, подсветка.
   Они одинаковые во всех браузерах, почти бесплатные и дают большую часть узнаваемости.
6. **Картинку за стеклом не клонируем из DOM.** Источники: живой фон через `backdrop-filter: url()`
   (только Chromium), `-moz-element()` (только Firefox), копия одной `<img>` или CSS-фона (везде),
   постер для видео. Над произвольным DOM в Safari будет матовое стекло, и это осознанное решение.
7. **Честно о пределе:** даже лучший SVG-путь в Safari считает процессор. 60 fps с живым преломлением
   при быстрой прокрутке на iPhone этим путём недостижимы. Поэтому на быстрой прокрутке матовое.

## 1. Почему без WebGL и чем за это платим

| | SVG + копия (этот проект) | WebGL по текстуре (другой проект) |
|---|---|---|
| Над чем работает | картинка, CSS-фон, постер; в Chromium и Firefox — любой DOM | только картинка, видео, canvas |
| Safari macOS | процессор, урезанная цепочка, живое на медленной прокрутке | видеокарта [ист.] |
| iPhone | «жидкое в покое» [гипотеза] | видеокарта, не мерили |
| Вес | ~7–9 КБ JS + ~2 КБ CSS [оценка] | ~6–10 КБ JS + шейдер |
| Отказы | тихо пустое при неудачном фильтре (Safari) | потеря контекста, лимит 16 контекстов, память iOS |
| Одинаково ли выглядит | нет: в Safari выборка ближайшим пикселем, в Chrome сглаженная [ист.: код WebKit] | да |
| Текст и ссылки внутри стекла | остаются DOM | остаются DOM |

Плюсы SVG-пути: ноль новых технологий, работает без JS на уровне L1, в Chromium и Firefox умеет
преломлять живой DOM (WebGL не умеет), нет риска потери контекста и лимитов памяти canvas на iOS.

## 2. Уровни (что видит человек)

| Уровень | Название | Что на экране | Чем считается |
|---|---|---|---|
| **L0** | Плашка | Плотная тонированная заливка 85–95 %, светлая кромка, тень. Без прозрачности | CSS, ничего не стоит |
| **L1** | Матовое (Apple Regular) | `backdrop-filter: blur(16–20px) saturate(1.8)`, тон, кромка, блик, тень | видеокарта во всех движках [ист.] |
| **L2** | Жидкое в покое | В покое — преломление у кромки, как L3. При прокрутке и смене слайда плавно меняется на L1 | один пересчёт фильтра на остановку |
| **L3** | Жидкое лёгкое | Живое преломление при медленной прокрутке, 1 проход смещения, аберрация слабая или нет | процессор (Safari, Firefox) |
| **L4** | Жидкое полное | Живое преломление, 3 прохода (аберрация), точная карта; в Chromium поверх любого DOM | видеокарта (Chromium) |

L1 — чистый CSS и включается без JS (класс по умолчанию в стилях плагина). JS только повышает уровень.
Поэтому при ошибке в JS, выключенном JS или отказе фильтра человек видит матовое стекло, а не пустоту.

Ось **«что происходит»** накладывается на уровень (подробно в разделе 7):

| Состояние | L4 | L3 | L2 |
|---|---|---|---|
| покой | жидкое | жидкое | жидкое |
| медленная прокрутка (< порога, см. 7.1) | жидкое | жидкое | матовое |
| быстрая прокрутка, инерция | жидкое | матовое | матовое |
| смена слайда под стеклом | жидкое, две линзы | матовое на 0,9 с | матовое на 0,9 с |

## 3. API

### 3.1 Подключение

Файлы рядом с сайтом, без CDN: `assets/liquid-glass/lg.js` (ES-модуль), `lg.css`.

Без JS-кода, атрибутами:
```html
<link rel="stylesheet" href="/assets/liquid-glass/lg.css">
<script type="module" src="/assets/liquid-glass/lg.js"></script>

<nav class="nav__row" data-lg="bar" data-lg-over="#hero-photo"> … </nav>
<button class="video__btn" data-lg="dot" data-lg-over="poster"> … </button>
<figcaption data-lg="dot" data-lg-over="closest img"> … </figcaption>
```
`lg.js` при загрузке находит `[data-lg]` и вызывает `attach`. Новые элементы — через `LG.scan(root)`.

Из JS:
```js
import { LG } from '/assets/liquid-glass/lg.js';

const glass = LG.attach(document.querySelector('.nav__row'), {
  preset: 'bar',                 // 'bar' | 'dot' | 'card' — набор значений ниже
  over: '#hero-photo',           // откуда картинка: 'backdrop' | 'auto' | селектор | Element | 'poster' | 'none'
  overWhen: () => true,          // когда жидкое уместно (у сайта: «под шапкой только фото»)
  tier: 'auto',                  // 'auto' | 0..4 — принудительно
  maxTier: 4,                    // потолок, например 2 для страницы с тяжёлым видео
  refraction: { rim: 4.5, bend: -140, profile: 'gauss' },  // 'gauss' | 'squircle'
  chroma: { spread: 0.12, mode: 'auto' },                  // 'auto' | 'off' | '2pass' | '3pass'
  soft: 1.3,                     // смягчение после смещения, px; 0 — без прохода
  edge: 'mirror',                // за краем картинки: 'mirror' | 'clamp' | 'none'
  frost: { blur: 18, saturate: 1.8 },                      // как выглядит L1
  tone: 'auto',                  // 'auto' | 'light' | 'dark' | функция
  motion: 'auto',                // 'auto' | 'live' | 'rest' (всегда как L2) | 'off'
});

glass.tier;                      // текущий уровень, 0..4
glass.set({ refraction: { bend: -120 } }); // пересобрать фильтр (новый id, см. 5.6)
glass.refresh();                 // пересчитать геометрию (после смены раскладки)
glass.setSource(img);            // сменить картинку (слайд); вернёт Promise после decode()
glass.destroy();                 // убрать всё, вернуть элемент как был

LG.config({ governor: true, debug: false, userPref: 'auto' }); // userPref: 'auto' | 'frost' | 'off'
LG.engine;                       // { name: 'webkit'|'blink'|'gecko', mobile, ... } — для отладки
```
События на элементе: `lg:tier` (`detail: { from, to, reason }`), `lg:fallback` (фильтр отключён
регулятором). Отладка: `?lg-debug` показывает уровень, причину и счётчик кадров в углу; настройки из
`localStorage` на живом сайте не подмешиваются (замечание G14 аудита).

### 3.2 Пресеты (значения из лаборатории владелец сайтаа, `CONTEXT.md`)

| Пресет | rim | bend | spread | soft | Для чего |
|---|---|---|---|---|---|
| `bar` | 4.5 | −140 | 0.12 | 1.3 | шапка-капсула |
| `dot` | 8 | −40 | 0.05 | 0.8 | кнопки ▶, подписи |
| `card` | 10 | −60 | 0.06 | 1.0 | крупные панели (на будущее) |

Общие CSS-переменные (как сейчас на сайте): `--lg-tint` (тон 26 %), `--lg-top` (свет сверху 7 %),
`--lg-rim` (кромка 40 %), `--lg-drop` (тень 70 %), `--lg-light-angle` (угол блика, `@property <angle>`).

### 3.3 Что плагин строит в DOM

```
host  (position: relative; isolation: isolate; border-radius как у дизайна; БЕЗ will-change и 3D)
├─ .lg-frost        L1: backdrop-filter, тон. Всегда есть, opacity 0/1
├─ .lg-lens         filter: url(#lg-N); aria-hidden; contain: paint
│   └─ .lg-clip     overflow: hidden; border-radius: inherit
│       ├─ img.lg-copy    копия фона, только 2D translate
│       └─ img.lg-mirror  отражённая полоса для edge: 'mirror'
├─ .lg-sheen        ::before — кромка и блик, ::after — подсветка (CSS, раздел 6)
└─ содержимое host  текст и ссылки, z-index выше
```
Правила из опыта Safari [S27]:
- внутри `.lg-lens` нельзя `translate3d`, `will-change`, анимации `transform` и `opacity` у потомков:
  потомок уходит в свой слой, и фильтр его не видит;
- область фильтра только в долях элемента (`objectBoundingBox`), не в пикселях;
- без `color-interpolation-filters="sRGB"` на `<filter>`;
- при любой пересборке фильтра — новый `id`.

Копии: `alt=""`, `decoding="async"`, тот же `loading`, что у оригинала (G8 аудита), заводятся при
первом входе в зону видимости (IntersectionObserver), а не на загрузке.

## 4. Откуда берётся картинка за стеклом

### 4.1 Источники по порядку предпочтения

| `over` | Источник | Где работает | Живое? | Цена |
|---|---|---|---|---|
| `backdrop` | `backdrop-filter: url(#lg-N)` — браузер сам отдаёт фон | **только Chromium** [ист.]. Safari не умеет [S27], Firefox молча рисует пусто [ист.] | да, любой DOM | видеокарта, почти бесплатно |
| `-moz-element` (авто в Firefox) | `background: -moz-element(#id)` у копии | только Firefox [ист.] | да, любой элемент | перерисовка элемента при каждом его изменении [ист.: Glass-HQ] |
| селектор `<img>`/`<picture>` | копия с тем же `currentSrc`, повтор `object-fit`/`object-position` | везде | при смене слайда — `setSource` | декодированная картинка общая с оригиналом [гипотеза] |
| элемент с CSS-фоном | копия `div` с тем же `background-*` | везде | нет | как у `<img>` |
| `poster` (видео) | постер `<video>` как `<img>` | везде | нет | Safari не накладывает SVG-фильтр на живое `<video>` и, по lore-glass, на canvas [ист.] |
| `none` / произвольный DOM в Safari | нет копии | — | — | уровень не выше L1 |

`over: 'auto'`: Chromium → `backdrop`; Firefox → `-moz-element` для произвольного элемента, копия
для `<img>`; Safari → копия, если под стеклом картинка, иначе L1.

Почему не клонируем DOM: удваивает стиль, раскладку и отрисовку, упирается в предел буфера фильтра
WebKit 4096² [ист.: код WebKit], не повторяет sticky и анимации, дублирует текст для скринридеров.
От этого уже отказались 29.10.

### 4.2 Выравнивание копии без чтения раскладки на каждом кадре

Сейчас на каждый `scroll` вызываются `getBoundingClientRect()` у фото и шапки (G6 аудита). В плагине:
- положение картинки в координатах документа и положение стекла во вьюпорте считаются **один раз**
  и по `ResizeObserver` (наблюдаем и картинку, и host — G9), а также по `load` шрифтов;
- в кадре только `scrollY`: `ty = imgTopDoc − scrollY − hostTopViewport`. Ноль чтений раскладки;
- копию двигаем, только если сдвиг > 0,5 px устройства;
- для `object-fit: cover` масштаб и смещение копии считаются один раз из `naturalWidth/Height`.

Экспериментальный режим без JS в кадре [гипотеза]: копия — `div` с `background-image` слайда, а
положение задаёт CSS-анимация `background-position-y` по шкале прокрутки (`animation-timeline: scroll()`,
есть в Safari 26 [ист.]). `background-position` не уходит в композитор, поэтому потомок не выносится
в отдельный слой и фильтр его видит. Анимировать `translate` так нельзя: композиторная анимация вынесет
потомка в слой, и преломление пропадёт [S27, то же правило]. Работа фильтра от этого не меньше,
выигрыш только в синхронности. Проверить в Safari.

### 4.3 Край картинки (`edge`)

Сильный изгиб (`bend −140`) берёт пиксели на десятки px за кромкой. У верха страницы над фото пусто.
- `mirror` — отражённая полоса картинки над ней (как сейчас, `scaleY(-1)`), высотой `|bend|/2 + 3·rim`,
  а не на всю высоту фото: меньше рисовать;
- `clamp` — полоса из крайней строки (копия с `object-position` и растяжением полосы 1 px);
- `none` — пусто, изгиб у края будет тёмным.

### 4.4 Что запекаем при сборке (build.py)

Картинки свои, поэтому часть работы фильтра можно сделать один раз на сервере сборки:
- **размытие и насыщенность копии**: `hero-N.lg.webp` с размытием σ ≈ 2 px и `saturate 1.6`, ширина
  1280 px (Mac) и 768 px (телефон). Из фильтра уходит `feGaussianBlur` по картинке, из CSS — `filter`
  у копии. Работа самого фильтра от меньшей картинки не уменьшается (она считается в пикселях
  области фильтра [ист.: код WebKit]), но декодирование и память — да;
- **тон**: средняя яркость полосы под шапкой с шагом 40 px → `data-lg-tone="0.31,0.35,…"`. Убирает
  `drawImage` + `getImageData` из прокрутки (G7, S3 аудита);
- **карта изгиба** (если пройдёт эксперимент 5.3 M2/M3): PNG по форме и размеру из пресета.

## 5. Как считается преломление

### 5.1 Общая схема фильтра

```
карта изгиба (R = сдвиг по X, G = по Y, 0.5 = ноль)
       │
SourceGraphic (копия) ──► feDisplacementMap ×1..3 ──► [сборка каналов] ──► [смягчение] ──► обрезка по SourceAlpha
```
Цена в Safari и Firefox ≈ **пиксели области фильтра × число примитивов × кадры, где под стеклом что-то
сдвинулось** [ист.: код WebKit, Outpace]. Каждое решение ниже уменьшает один из трёх множителей.

### 5.2 Область фильтра под размер

Сейчас `x=-0.2 width=1.4 y=-0.5 height=2` для всех элементов (2,8 площади шапки). Нужно поле около
3σ размытия маски: `pad = ceil(3·rim) + 2` px.
```
x = -pad / w;   width  = 1 + 2·pad / w
y = -pad / h;   height = 1 + 2·pad / h
```
Шапка 1232×60 CSS px, DPR 2: было 3450×240 ≈ 0,83 Мпикс, станет (1232+32)×(60+32)×4 ≈ 0,47 Мпикс
(−44 %) [оценка]. Пересчёт по `ResizeObserver` с задержкой 150 мс и новым id.
Важно: `CONTEXT.md` говорит, что без запаса «у прямых краёв нет изгиба». Запас 3σ должен это закрыть,
но это надо проверить в Safari на решётке (раздел 11, п. 5).

Компенсация `scale` по движку (в долях браузеры переводят его в px по-разному, замер tfdmendes [ист.]):
Blink — по ширине для X и Y; WebKit — X по ширине, Y по высоте; Gecko — по √((w²+h²)/2). Плагин
делит `bend` на нужный множитель, чтобы изгиб в px совпадал во всех движках. Без этого шапка в Chrome
и Safari гнётся по-разному — одна из причин «в Chrome выглядит иначе».

### 5.3 Карта изгиба: три способа

**M1. Карта считается в фильтре (проверено в Safari, сейчас так).** SourceAlpha → белая маска →
`feGaussianBlur(rim)` → два `feConvolveMatrix` (Собель X и Y) → каналы R и G → сборка. Работает в
Safari 27 [S27], но это 7 примитивов на каждом кадре, хотя карта от кадра к кадру не меняется. Улучшения:
- сборку R и G делать не `feComposite arithmetic`, а `feComposite operator="lighter"` (WebKit рисует его
  как plus-lighter, Glass-HQ так ушёл от программного arithmetic, который занимал > 50 % времени
  фильтра [ист.]) или `feBlend mode="screen"` (в каждом слое ненулевой только свой канал, screen даёт
  ровно сумму). Оба — [гипотеза: проверить в Safari, что не рисует пусто];
- профиль кромки ближе к Apple: `feComponentTransfer type="table"` на размытой маске перед Собелем
  превращает гаусс в выпуклый squircle `y = ⁴√(1−(1−x)⁴)` (kube.io [ист.]). Это один дешёвый проход
  по таблице. Опция `profile: 'squircle'` [гипотеза: в Safari не проверено].
- `color-interpolation-filters="sRGB"` поставить **на отдельные примитивы**, а не на `<filter>`: на
  `<filter>` Safari рисует пусто [S27], а на примитивах не пробовали. Если сработает, уходят переводы
  sRGB↔linearRGB между шагами, и нейтраль 0.5 перестаёт «уплывать» (возможный постоянный сдвиг всей
  картинки до ~30 px при bend −140, аудит) [гипотеза].

**M2. Готовая карта внутри SourceGraphic (без feImage) [гипотеза].** Карту-картинку (PNG из сборки или
canvas → `data:` в обычном HTML `<img>`, это в Safari работает) кладём внутрь `.lg-lens` рядом с
копией, но за видимой частью области фильтра. В фильтре `feOffset` ставит её на место, `feComposite in`
обрезает по форме, результат идёт в `in2` смещения. Вместо 7 примитивов — 2–3, и карта может быть
честной (SDF + Снеллиус, как у kube.io и Outpace). Минусы: область фильтра вырастает на зону карты.
Это частично гасится подобластями примитивов (`x/y/width/height` у примитивов, как у PallavAg [ист.]),
но PallavAg пишет, что iOS WebKit неверно ставит подобласти в долях [ист.]. Это главный эксперимент
для Mac: если выигрыш по времени есть, а подобласти работают, это лучший Safari-путь.

**M3. feImage с картой (Chromium, Firefox; Safari — если пройдёт эксперимент).** Карта один раз
считается в canvas (четверть с зеркалированием, как у Aave [ист.]), кэш по размеру и форме.
- Chromium и Firefox: `data:` работает [ист.]. Цепочка короче всех.
- Safari: `data:` и `blob:` у нас рисуют пусто [S27]. Три непроверенные лазейки:
  1. `img.decode()` той же ссылки до вставки, затем дважды новый id через 60 и 250 мс (tfdmendes пишет,
     что так работает в Safari 27 [ист.]); PR WebKit 68614 описывает именно ошибку «feImage не
     уведомляет CSS-фильтр после загрузки» [ист.];
  2. `href="#lg-map-N"` на SVG-элемент в том же документе (`<image>` с картой). Smashing Magazine
     (2021) пишет, что ссылка на фрагмент работает **только в Safari** [ист., старый источник];
  3. внешний файл карты с того же сайта.
  Если хоть одна работает в Safari 27, в Safari переходим на M3, M1 остаётся запасом.

Выбор карты делает плагин по движку и по результатам **пробного рендера** (раздел 8.2).

### 5.4 Цепочки по уровням

| Уровень | Карта | Смещение | Аберрация | Сборка | Смягчение | Примитивов |
|---|---|---|---|---|---|---|
| L4 (Chromium, `backdrop`) | M3 | 3 прохода (R, G, B с масштабом ×1, ×(1+s), ×(1+2s)) | да | `lighter` / `screen` | `feGaussianBlur soft` | ~9 |
| L3 Safari | M1 улучшенная (или M2/M3 по эксперименту) | 1 проход | нет или «2 прохода» по опции | — | нет (размытие запечено в копию) | ~8 (M1) / ~4 (M2, M3) |
| L3 Firefox | M3 | 1 проход | нет | — | `soft` (размытие в WebRender на видеокарте [ист.]) | ~4 |
| L2 | как L3 своего движка, но можно полную аберрацию: считается раз на остановку | 1–3 | да | | | ~8–14 |

«Аберрация в 2 прохода» для L3 по опции: проход A (масштаб s) и проход B (s·(1+2·spread));
R берём из B, G и B из A (`feColorMatrix` ×2 + `lighter`). Цвет расходится только у кромки, где карта
не нейтральна. +3 примитива вместо +8 у трёх проходов [гипотеза].

Финал всегда `feComposite operator="in" in2="SourceAlpha"`: обрезка по форме. Это не arithmetic, дешёво.

### 5.5 Сравнение работы на кадр (шапка Mac, DPR 2)

| Вариант | Пикселей области | Примитивов | Относительная работа |
|---|---|---|---|
| Сейчас | 0,83 Мп | 17 (4 arithmetic) | 100 % |
| Область под кромку | 0,47 Мп | 17 | ~57 % |
| + 1 проход, без arithmetic, без soft | 0,47 Мп | 8 | ~27 % |
| + карта M2/M3 | 0,47–0,55 Мп | 4 | ~13–16 % |

[оценка: работа ∝ пиксели × примитивы; разная цена примитивов не учтена — Собель и displacement дороже
colorMatrix, поэтому реальный выигрыш у M2/M3 может быть больше]

### 5.6 Пересборка фильтра

Фильтр — чистая функция `(id, opts, box) → строка SVG` (как `filter()` в нынешнем glass.js). Пересборка
только при смене размера, пресета или уровня. Каждый раз новый id `lg-<n>` [S27: Safari кэширует по
id]. В Safari 27 исправили «фильтр по url(#id) не обновлялся» [ист.], возможно, трюк уже не нужен, но
он ничего не стоит — оставляем. Один `<svg width=0 height=0 aria-hidden>` на страницу, старые
`<filter>` удаляются.

## 6. Аберрация, блик, кромка, тень, тон

### 6.1 Аберрация
Внутри фильтра (5.4): L4 — 3 прохода; L3 — выкл. или 2 прохода; L2 — можно полная. По Apple аберрация
едва заметна и в материалах Apple не упоминается [ист.: apple.md], поэтому первой уходит при нехватке
кадров. Для кнопок (`spread 0.05`) всегда выкл.: её там не видно (G5 аудита).

### 6.2 Блик и светлая кромка — CSS, вне фильтра
`.lg-sheen::before`: рамка 1–1,5 px, вырезанная маской, с градиентом по углу `--lg-light-angle`:
```css
.lg-sheen::before {
  content: ""; position: absolute; inset: 0; border-radius: inherit; padding: 1px;
  background: linear-gradient(var(--lg-light-angle, 160deg),
    rgb(255 255 255 / .65), transparent 38%, transparent 62%, rgb(255 255 255 / .22)) border-box;
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor; mask-composite: exclude;
}
```
Запасной вариант (если маска в каком-то движке подведёт) — три `inset box-shadow`, как сейчас в
`.is-glass::before` [S27: на сайте работает]. Внутренний «объём»: `inset 0 1px 0`, `inset 0 -1px 0`
со слабой нижней кромкой — ярко сверху-слева, тускло снизу-справа, как у Apple.

Отказались от `feSpecularLighting`: он рисует блик по карте высот прямо в фильтре, но это ещё
программные проходы в Safari, а разработчики фильтров называют освещение самым медленным примитивом
[ист.: обсуждение на lobste.rs, мнение, не замер].

Движение блика (опция `light: 'pointer'`): угол `--lg-light-angle` от курсора, через `@property` с
типом `<angle>`. Меняется переменная у `::before`, фильтр не трогается. При «Уменьшить движение» не
двигаем. Проверить в Safari, что анимация переменной поверх `.lg-lens` не выносит линзу в слой
[гипотеза].

Подсветка под курсором и при нажатии: `::after` с `radial-gradient(circle at var(--x) var(--y), …)`
и `mix-blend-mode: plus-lighter`.

### 6.3 Тень
`box-shadow` на самом host: `0 10px 30px -14px var(--lg-drop), 0 1px 3px …`. Не внутри фильтра, не
`filter: drop-shadow` (в Safari 27 у него как раз чинили перерисовку за границей [ист.]). Над фото
тень сильнее, над белым слабее — по `data-lg-tone`.

### 6.4 Тон
`tone: 'auto'` берёт яркость полосы из `data-lg-tone` (сборка, 4.4) с гистерезисом 0,42/0,58 (как
сейчас). Если данных нет — один раз `drawImage` в 48×6 при смене слайда, не при прокрутке. Класс
`is-dark` меняет цвет текста, кромку и тень с `transition` 200–300 мс. Фильтр не трогается.
Для Apple Clear над фото: локальное затемнение ~35 % только под текстом (радиальный градиент) [ист.:
HIG], а не заливка всей капсулы.

## 7. Движение: когда считать фильтр

### 7.1 Автомат состояний
```
           scroll (скорость v)                 scrollend / 150 мс тишины
  ПОКОЙ ───────────────────────► ДВИЖЕНИЕ ─────────────────────────────► ПОКОЙ
  жидкое                          L4: жидкое                             поставить копию (1 раз),
                                  L3: жидкое, если v < V, иначе матовое  показать линзу, спрятать
                                  L2: матовое сразу                      матовое за 200 мс
```
- Скорость `v = |ΔscrollY| / Δt` в пассивном `scroll`. Порог `V` для L3: начально 800 px/с, подбирать
  по замеру (в performance.md предлагали 1200–2000; для Safari, где кадр дорогой, порог ниже).
- Переход жидкое → матовое мгновенный (нельзя анимировать, пока фильтр пересчитывается);
  матовое → жидкое: сначала линза становится видимой под матовым слоем, фильтр считается один раз,
  затем `.lg-frost` уходит в `opacity: 0` за 200 мс. Анимируется прозрачность **матового слоя над
  линзой**, а не самой линзы и не её потомков, поэтому фильтр пересчитывать не нужно [гипотеза].
- `scrollend` есть в Safari 26.2+, Chrome 114+, Firefox 109+ [ист.]; запасной таймер 150 мс.
- Спрятанная линза — `visibility: hidden` (не `opacity: 0`): не рисуется и не держит буферы фильтра.

### 7.2 Смена слайда
- L2/L3: на время кроссфейда фото (0,9 с) — матовое; новая копия ставится скрытой после
  `await img.decode()` (S1, S5 аудита), в конце кроссфейда — обратно жидкое. Кроссфейда **внутри**
  линзы больше нет (C2 аудита: 54 пересчёта на CPU и риск выноса слоя).
- L4 (Chromium, видеокарта): две линзы, у каждой своя копия, анимируется `opacity` линз. В режиме
  `backdrop` копии нет вовсе: браузер сам видит кроссфейд.

### 7.3 Не работать, когда не видно
- IntersectionObserver на картинку-источник с `rootMargin` на высоту стекла: картинка ушла из-под
  стекла → линза `hidden`, слушатель прокрутки снят, уровень по факту L1 (шапка ниже фото матовая —
  это и логика Apple Regular над текстом [ист.]).
- `overWhen()` — правило сайта поверх этого (у сайт-пример: под шапкой не должна быть плашка заголовка).
- `visibilitychange` → всё стоп.
- `matchMedia(...).addEventListener('change')` для всех медиазапросов (G10 аудита).

## 8. Как плагин выбирает уровень

### 8.1 Движок и устройство
- **WebKit:** `'webkitConvertPointFromNodeToPage' in window` (так у Amir-Abushanab [ист.]) или
  `'GestureEvent' in window`, плюс `navigator.vendor === 'Apple Computer, Inc.'`. Safari 27 убрал часть
  старых интерфейсов [ист.: WebKit, Safari 27], поэтому сигналов несколько, и проверить, что они живы.
  На iOS все браузеры — WebKit [ист.].
- **Gecko:** `CSS.supports('selector(:-moz-focusring)')` или `CSS.supports('background', '-moz-element(#a)')`.
- **Blink:** `navigator.userAgentData` есть (только Chromium) и не WebKit/Gecko.
- **Телефон/планшет:** WebKit + `navigator.maxTouchPoints > 1` (iPad с трекпадом отдаёт
  `pointer: fine`, аудит), `pointer: coarse`, `hardwareConcurrency ≤ 4`, `deviceMemory ≤ 4` (только
  Chromium), `saveData`.
- **Не верить `@supports` для `backdrop-filter: url()`:** Firefox и Safari отвечают «да», но рисуют
  пусто [ист.].

Начальный уровень:

| Среда | Старт | Потолок |
|---|---|---|
| Chromium десктоп | L4 (`backdrop`) | L4 |
| Chromium Android, ≥ 6 ядер | L3 (копия или `backdrop`, 1 проход) | L4 по регулятору |
| Chromium Android, слабый | L1 | L3 |
| Safari macOS 27+ | L3 | L3 |
| Safari macOS < 27 | L2 | L3 по регулятору [не проверено] |
| iOS/iPadOS (любой браузер) | L2 | L3 по регулятору |
| Firefox десктоп | L3 | L3 |
| Firefox Android | L1 с малым размытием (8 px) | L1 |
| нет `backdrop-filter` | L0 | L0 |

### 8.2 Пробный рендер (защита от «пусто»)
Главная беда Safari — элемент молча рисуется пустым [S27]. Прочитать пиксели DOM из JS нельзя, поэтому:
- набор фильтров и атрибутов, проверенных [S27], зашит как «безопасный» для WebKit; всё
  экспериментальное (M2, M3 в Safari, sRGB на примитивах, `lighter`) включается **только по флагу**
  `LG.config({ experiments: [...] })` до тех пор, пока не пройдёт A/B в настоящем Safari;
- в Chromium и Firefox, где это возможно, можно проверить карту на canvas (сама карта — canvas, её
  содержимое известно), но не результат фильтра.
Честно: автоматического пробного рендера результата SVG-фильтра в вебе нет. Защита — белый список
проверенного плюс матовый слой, который лежит под линзой и виден, если линза пустая. Пустая линза
поверх `.lg-frost` даёт матовое стекло, а не дыру [гипотеза: нужно, чтобы пустая линза была прозрачной,
а не непрозрачной; по описанию «рисуется пустым» так и есть, проверить].

### 8.3 Регулятор кадров
- В состоянии «движение» с живым жидким (L3/L4) считаем интервалы rAF (как зонд из performance.md).
- Если за окно 60 кадров p95 > 1,5 × период обновления или два кадра > 50 мс — спуск на ступень
  (L4 → L3 → L2), событие `lg:tier` с причиной.
- Решение запоминается в `sessionStorage` (в `try/catch`), на следующей странице старт сразу с него.
- Подъём обратно не делаем внутри сессии (иначе стекло «мигает» уровнями).
- В режиме энергосбережения iOS частота может падать до 30 Гц [не проверено] — период берём из
  медианы интервалов, а не 16,7 мс.

## 10. Ожидаемая скорость

Опора: замер владелец сайтаа в Safari 27 на Mac — нынешняя цепочка над фото даёт 60 fps, худший кадр 33 мс
[S27]; Chrome — жидкое при прокрутке худший кадр 18 мс против 10 мс у матового при 120 Гц [Chrome].
Остальное — **[оценка]** по формуле «работа ∝ пиксели × примитивы» от этих двух точек, без учёта
разной цены примитивов. Всё в таблице, кроме двух опорных цифр, нужно мерить.

| Уровень | Mac Safari 27 | Mac Chrome | iPhone Safari (капсула 361×56, DPR 3) |
|---|---|---|---|
| L1 | 60 fps, как сейчас на сайте | 120 fps | 60 fps, CABackdropLayer [ист.] |
| L2 | прокрутка = L1; один пересчёт ~5–15 мс при остановке | — | прокрутка = L1; один пересчёт ~10–40 мс при остановке, т. е. один длинный кадр в покое, незаметный под матовым слоем |
| L3 (M1 улучш.) | худший кадр ~10–15 мс вместо 33; живое до порога скорости | — | ~0,3 Мп × 8 → 5–15 мс на кадр; на грани, только если регулятор разрешит |
| L3 (M2/M3) | ~5–8 мс | — | ~3–8 мс |
| L4 | — | ≈ как сейчас: худший 18 мс при 120 Гц, на 60 Гц-экранах без пропусков | — |

Отставание копии от прокрутки (L3) — 1 кадр и больше при нагрузке: прокрутку двигает композитор, а
копию JS [ист.: svgwg #1142]. При 800 px/с это ~13 px за кадр. Поэтому выше порога — матовое.
Firefox: `feDisplacementMap` и `feImage` идут на процессор [ист.: Mozilla, Glass-HQ], ожидаем примерно
как Safari; размытие на видеокарте.

Память iPhone [оценка]: область фильтра шапки ~0,3 Мп × 4 Б ≈ 1,2 МБ на промежуточный буфер, × 8
примитивов ≈ 10 МБ на время пересчёта (сейчас до ~35 МБ). В L2 это раз на остановку.

Пороги «годится» — из performance.md: Mac p95 ≤ 16,7 мс, худший ≤ 25 мс, 0 кадров > 50 мс;
iPhone p95 ≤ 17 мс, худший ≤ 33 мс, без вылетов. Не проходит — регулятор опускает уровень.

## 11. Что проверить в настоящем Safari до кода (по пользе)

Отдельная A/B-страница в лаборатории, каждое — включить, прокрутить, посмотреть, записать худший кадр:
1. Флаг Safari «Разработка → Флаги функций → Accelerated Filter Rendering» вкл/выкл: подтверждает, что
   узкое место — процессорный фильтр [ист.: код WebKit, флаг выключен по умолчанию].
2. feImage: (а) `data:` + `img.decode()` + новый id через 60/250 мс; (б) `href="#фрагмент"`;
   (в) внешний PNG своего сайта. Если хоть одно работает — карта M3 в Safari.
3. `color-interpolation-filters="sRGB"` на каждом примитиве, а не на `<filter>`.
4. `feComposite operator="lighter"` и `feBlend mode="screen"` вместо arithmetic: не пусто ли, быстрее ли.
5. Область фильтра под кромку (5.2): есть ли изгиб у прямых краёв капсулы (решётка под стеклом).
6. M2: карта в SourceGraphic + `feOffset` + подобласти примитивов; отдельно на iPhone (подозрение на
   неверные подобласти в долях).
7. L2: остаётся ли фильтр посчитанным, пока страница стоит (Timelines → Rendering Frames пустые);
   не пересчитывается ли он при анимации `opacity` матового слоя над линзой.
8. Пустая линза прозрачна, а не чёрная (защита 8.2).
9. `feComponentTransfer type="table"` (профиль squircle).
10. Сигналы распознавания WebKit (8.1) живы в Safari 27.
11. Копия через `background-position` по `animation-timeline: scroll()` (4.2): видна ли в фильтре.
12. Гипотеза из performance.md: линза вдвое меньше + `scale(2)` у родителя — уменьшает ли работу.
13. На iPhone (Web Inspector по кабелю): цена одного пересчёта для L2 и кадр L3.

| В Chrome и Safari стекло выглядит по-разному | высокая | разный изгиб и зубчатость кромки | компенсация `scale` (5.2); выборка в Safari ближайшим пикселем [ист.] — сгладить `soft` или смириться |

| Обновление Safari меняет поведение (PR 68613/68614, ускоренные фильтры) | средняя, в лучшую сторону | старые обходы могут стать лишними или вредными | всё по движку и версии, флаги экспериментов, регулярный A/B в лаборатории |
| `-moz-element()` уберут из Firefox | низкая-средняя | нет живого фона в Firefox | автоматически копия или L1 |
| Предел буфера фильтра WebKit 4096² | низкая для шапки | размытый или пустой фильтр на огромных панелях | предупреждение в debug, если площадь > 2,5 Мп (как у PallavAg) |
| Память iOS при многих стёклах | низкая | вылет вкладки | лимит активных линз (по умолчанию 4), остальные L1 |
| Нет `prefers-reduced-transparency` в Safari | точно | человек с этой настройкой видит стекло | ручной переключатель, контраст текста без опоры на стекло |
| Тонировка панелей Safari 26 от фиксированной шапки с `backdrop-filter` | средняя | панели браузера красятся под шапку [ист.: 1ar.io] | матовый слой — абсолютный дочерний `aria-hidden`, сам контейнер шапки прозрачный; проверить на iPhone |

## 14. Порядок работ (если выбирать этот путь)

1. A/B-страница из раздела 11 и прогон в настоящем Safari (владелец сайта, ~20 минут) + iPhone по кабелю.
2. Генератор фильтра: область под размер, цепочки по уровням, компенсация `scale`, белый список.
3. Каркас `LG.attach`: DOM из 3.3, L0/L1 на CSS, источники `img`/`poster`/`backdrop`.
4. Автомат движения (L2) и регулятор кадров; копия без чтения раскладки.
5. Слой CSS: кромка, блик, тень, тон из сборки; доступность.
6. Сборка: запечённые копии `*.lg.webp`, `data-lg-tone`, карта (если M2/M3 прошли).
7. Лаборатория как стенд: счётчик кадров, переключатель уровней, сравнение с WebGL-вариантом на одной
   странице. Встраивание в `site-next/`, сайт не трогаем.
