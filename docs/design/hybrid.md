# Архитектура плагина: гибрид «по содержимому»

Дата: 30.10.2026, ночной прогон. Черновик проекта, кода пока нет. Сайт `<сайт>/` не трогал.

Угол проекта: **честное преломление только там, где под стеклом медиа (фото, видео, canvas).
Над текстом и интерфейсом стекло матовое и дешёвое, с бликами и кромкой. Режим переключается на лету,
по тому, что сейчас лежит под стеклом.**

Метки:
- **[S27]**: проверено в настоящем Safari 27 (по `CONTEXT.md`);
- **[ист.]**: по источникам, нами не проверено;
- **[Safari ?]**: в настоящем Safari не проверено, нужна проверка;
- **[оценка]**: расчёт на бумаге, не замер.

Опирается на `research/*.md`: apple.md, browsers.md, graphics.md, implementations.md, fresh.md,
performance.md, audit.md. Из них беру факты, здесь только то, что нужно для проекта.

## 0. Коротко

1. **Два движка вместо одного SVG-фильтра.** Над медиа преломление считает WebGL2-шейдер, а
   картинку за стеклом он берёт из самого `<img>`/`<video>` как текстуру. Захватывать DOM не нужно.
   Над всем остальным работает `backdrop-filter: blur() saturate()`, который во всех движках идёт на
   видеокарте. SVG-фильтров в плагине нет совсем. Так мы обходим и программный путь фильтров в Safari
   ([код WebKit: `AcceleratedFiltersEnabled` выключен](https://github.com/WebKit/WebKit/blob/main/Source/WTF/Scripts/Preferences/UnifiedWebPreferences.yaml)),
   и все грабли Safari 27 с feImage, sRGB, `userSpaceOnUse` и композитными слоями [S27].
2. **Кромка, блик и тень всегда рисуются в CSS, одинаково в обоих режимах.** Шейдер добавляет только
   то, что видно сквозь стекло: изгиб, аберрацию, тон. Поэтому при переключении режима кромка не
   «прыгает»: меняется только прозрачность одного canvas.
3. **Для стекла, которое прокручивается вместе с медиа** (кнопка ▶ на видео, подпись на фото),
   картинка под стеклом не меняется при прокрутке. Шейдер рисует её один раз, а потом canvas просто
   едет с композитором. Перерисовок на прокрутке нет вообще, отставать нечему.
   Перерисовка на каждом кадре нужна только **фиксированному** стеклу (шапке).
4. **У шапки главный риск не скорость, а отставание** на кадр от нативной прокрутки
   ([разбор: WebGL Scroll Sync](https://hub.joyco.studio/logs/08-webgl-scroll-sync)). Лечим режимом:
   при быстрой прокрутке шапка уходит в матовое (композитор, без отставания), а жидкой становится на
   медленной прокрутке и в покое.
5. **Стекло знает, где в его области медиа, а где нет.** Маска покрытия уходит в шейдер. Если шапка
   стоит наполовину над фото, наполовину над белой плашкой текста, преломление будет только над фото,
   остальное останется матовым. Граница плавная.
6. Ожидаемо [оценка]: шейдер шапки на Mac около 0,1–0,3 мс видеокарты на кадр, на iPhone меньше 1 мс.
   Главный процессор занимают только uniform'ы и один draw call. Вес плагина около 8–10 КБ gzip, без
   зависимостей.

## 1. Из чего состоит стекло (слои)

```
host (элемент пользователя: .nav__row, кнопка ▶, подпись)     box-shadow (тень), isolation: isolate
 ├─ .lg-frost    absolute, inset 0, radius inherit, aria-hidden    backdrop-filter: blur(..) saturate(..) + тон
 ├─ canvas.lg-lens absolute, inset -pad, aria-hidden, pointer-events none   WebGL2: изгиб+аберрация+тон
 ├─ .lg-rim      absolute, inset 0, radius inherit, aria-hidden    ::before кромка-градиент, ::after подсветка
 └─ содержимое host (ссылки, текст, иконки)                        поверх всего, в обычном DOM
```

Почему так:
- **Ни один слой не лежит внутри SVG-фильтра.** Поэтому можно `translate3d`, `will-change`, анимации
  `opacity`. Правило «внутри фильтра только 2D translate» [S27] нас больше не касается.
- **Фон самого host прозрачный, матовость на дочернем слое.** Safari 26 красит свои панели по
  `background-color`/`backdrop-filter` фиксированных элементов у края экрана
  ([1ar.io](https://1ar.io/updates/safari-26-liquid-glass-web/)) [Safari ?]. Если `backdrop-filter`
  висит на абсолютном дочернем слое, этого поведения, по их данным, удаётся избежать.
- **Canvas шире host на `pad` с каждой стороны** (pad ≈ 2 px под сглаживание кромки). Форму стекла
  рисует сам шейдер по SDF с альфой. `overflow: hidden` + скругление не нужны, а значит, нет и бага
  Firefox, где WebGL-canvas в композитном слое не обрезается по `border-radius`
  ([Amir-Abushanab/liquid-glass-js](https://github.com/Amir-Abushanab/liquid-glass-js), комментарии в `mount.ts`).
- **Матовый слой всегда лежит под canvas.** В жидком режиме canvas непрозрачен там, где под ним медиа,
  и закрывает матовое. Там, где медиа нет, canvas прозрачен, и видно матовое. Переключение режима —
  это `opacity` у canvas, анимация на композиторе.

## 2. API

### 2.1 Подключение

Один ES-модуль и один CSS-файл, рядом с сайтом (без CDN):

```html
<link rel="stylesheet" href="/assets/liquid-glass.css">
<script type="module" src="/assets/liquid-glass.js"></script>
```

Декларативно, без своего JS (то, что нужно сайт-пример):

```html
<!-- медиа, через которое стекло умеет преломлять -->
<figure class="hero__photo" data-glass-media="stack">        <!-- стопка слайдов: активный = .is-on -->
  <img src="/img/hero-1-2000.webp" data-glass-src="/img/hero-1-768.webp" class="is-on" alt="…">
  <img src="/img/hero-2-2000.webp" data-glass-src="/img/hero-2-768.webp" alt="…">
  <figcaption data-glass-occluder>…</figcaption>                <!-- DOM поверх медиа: тут не преломлять -->
</figure>
<div class="hero__panel" data-glass-occluder>…</div>          <!-- плашка с текстом, налезает на фото -->

<!-- само стекло -->
<nav><div class="nav__row" data-glass="capsule" data-glass-preset="bar">…</div></nav>
<button class="video__btn" data-glass="circle" data-glass-preset="dot">▶</button>
```

Программно:

```js
import { glass } from '/assets/liquid-glass.js';

glass.configure({ debug: false, maxContexts: 4, quality: 'auto' });   // глобально, один раз

const media = glass.media(document.querySelector('.hero__photo'), {
  kind: 'stack',            // 'image' | 'video' | 'canvas' | 'stack'
  active: 'img.is-on',      // для stack: какой слой сейчас виден
  fade: 900,                // мс кроссфейда слайдов (повторяем в шейдере)
  tone: 'auto',             // 'auto' | 'light' | 'dark' | функция (img) => 'light'|'dark'
});
media.show(nextImg, { fade: 900 });   // слайдер сообщает о смене слайда (вместо события `slide`)

const g = glass.attach(document.querySelector('.nav__row'), {
  shape: 'capsule', preset: 'bar',
  rim: 14, thickness: 22, ior: 1.5, spread: 0.12, blur: 1.3, tint: 0.26,
});
g.on('mode', (e) => console.log(e.mode, e.reason));  // 'liquid' | 'frost' | 'solid'
g.set({ thickness: 18 });  // поменять параметры на лету (просто uniform'ы, без пересборки)
g.refresh();               // пересчитать геометрию (после смены разметки)
g.destroy();
```

### 2.2 Параметры стекла

| Параметр | По умолчанию (bar / dot) | Что делает | Куда идёт |
|---|---|---|---|
| `shape` | `capsule` / `circle` | `capsule`, `circle`, `rect` (+ `radius`), `auto` = из `border-radius` host | SDF в шейдере, радиус в CSS |
| `squircle` | `true` | непрерывная кривизна угла (норма L4, как у Apple) | SDF |
| `rim` | 14 / 18 px | ширина кромки, где идёт изгиб. Середина стекла не искажена | профиль высоты |
| `profile` | `squircle` | `squircle` ⁴√(1−(1−x)⁴) (по [kube.io](https://kube.io/blog/liquid-glass-css-svg/)), `circle`, `lip` | профиль высоты |
| `thickness` | 22 / 8 px | «толщина» стекла: максимальный сдвиг картинки у кромки. Знак задаёт направление | шейдер |
| `ior` | 1.5 | показатель преломления | `refract()` |
| `spread` | 0.12 / 0.05 | сила аберрации (расхождение цветов у кромки); 0 = выкл | шейдер |
| `samples` | `auto` (5 Mac / 3 телефон) | число спектральных выборок | шейдер, ветка компиляции |
| `blur` | 1.3 / 0.8 px | лёгкое размытие сквозь стекло | `textureLod` по мипмапам |
| `saturate` | 1.5 | насыщение сквозь стекло (у Apple цвет «сочнее») | шейдер и `.lg-frost` |
| `tint` | 0.26 | заливка тоном (из «тон 26 %» владелец сайтаа) | шейдер и `.lg-frost` |
| `frostBlur` | 20 px | размытие матового режима | `.lg-frost` |
| `light` | −60° | направление света для блика | CSS-переменная и uniform |
| `rimLight` | 0.40 | яркость светлой кромки («кромка 40 %») | CSS |
| `topLight` | 0.07 | свет сверху («свет сверху 7 %») | CSS |
| `shadow` | 0.70 | сила тени («тень 70 %»), над медиа ×1, над белым ×0,5 | CSS `--lg-sh` |
| `sync` | `auto` | `viewport` (стекло фиксированное) или `content` (едет с медиа); `auto` по `position` | обвязка |
| `fastScroll` | 600 px/с | выше этой скорости фиксированное стекло уходит в матовое | обвязка |
| `modes` | `['liquid','frost']` | разрешённые режимы; `['frost']` = только матовое | обвязка |

Числа «как у владелец сайтаа» (rim 4.5, bend −140 и т. д.) задавали σ размытия маски и масштаб
feDisplacementMap. В шейдере смысл у параметров другой (ширина кромки в px и сдвиг в px). Пересчитать
их надо в лаборатории **по решётке**: снять текущее SVG-стекло и шейдерное в Chrome на одной клетчатой
подложке и подогнать `rim`/`thickness`, чтобы сдвиг у кромки совпал. Значения в таблице — стартовые
[оценка: σ 4.5 px ≈ кромка 3σ ≈ 14 px].

### 2.3 Атрибуты и события

- `data-glass="capsule|circle|rect|auto"`, `data-glass-preset="bar|dot"`, `data-glass-*` для любого параметра (`data-glass-thickness="18"`).
- `data-glass-media="image|video|canvas|stack"`, `data-glass-src` (маленькая картинка для текстуры), `data-glass-tone="light|dark"` (тон заранее из build.py).
- `data-glass-occluder`: DOM поверх медиа, под ним стекло не преломляет (плашка с текстом, подпись).
- На host ставится `data-glass-mode="liquid|frost|solid"` и `data-glass-tone="light|dark"`. По ним сайт сам меняет цвет текста и иконок в шапке (Apple переключает мелкие элементы по фону, см. apple.md §7).
- Событие `glass:mode` на host (`detail: { mode, reason }`, причины: `no-media`, `fast-scroll`, `no-webgl`, `context-lost`, `budget`, `reduced-transparency`, `contrast`, `user`).
- `?glass=frost|liquid|off` и `?glass-debug=1` (HUD: режим, покрытие, fps, худший кадр, время шейдера). Никакого `localStorage` на живых страницах (audit G14).

## 3. Откуда берётся картинка за стеклом

Стекло **не снимает страницу**. Оно знает зарегистрированные медиа и их положение и само
вычисляет, какой кусок медиа лежит под ним.

### 3.1 Источники

| Источник | Как попадает в текстуру | Когда обновляется | Замечания |
|---|---|---|---|
| `<img>` | `await img.decode()` → `texImage2D(img)` → `generateMipmap` | один раз на картинку | Берём `data-glass-src` (768 px webp из build.py), а не 2000-пиксельный `currentSrc`: память GPU 1,5 МБ против 15 МБ ([performance.md §5.1](../research/performance.md)). Своё происхождение (same-origin), CORS не нужен |
| стопка слайдов (`stack`) | две текстуры: текущая и следующая; `mix(texA, texB, t)` в шейдере | при `media.show()` или при смене класса `.is-on` (MutationObserver на атрибут `class`) | Кроссфейд идёт в шейдере, а не 900-мс `opacity` слоёв под фильтром (audit C2) |
| `<video>` | `texImage2D(video)` по `requestVideoFrameCallback` | на каждом новом кадре видео, но не чаще 30 Гц; на паузе — ни разу | В Safari SVG-фильтр к живому видео вообще не применяется ([WebKit 184601](https://bugs.webkit.org/show_bug.cgi?id=184601)), так что WebGL тут единственный путь. Есть сообщение, что rVFC на играющем видео в WebKit роняет WebGL-контексты страницы ([orktes/jsui#74](https://github.com/orktes/jsui/pull/74), проверено в Playwright-WebKit, то есть **не доказательство**) [Safari ?]. Поэтому для WebKit запасной путь: опрос `video.currentTime` в rAF, а до первого кадра — `poster` |
| `<canvas>` | `texImage2D(canvas)` | по `media.invalidate()` | на будущее |
| HTML-in-Canvas | — | — | Только Chromium по origin trial ([Chrome](https://developer.chrome.com/blog/html-in-canvas-ot-changes)). В гибрид не входит: над DOM у нас матовое по замыслу |

На кнопках ▶ видео по умолчанию **в паузе**, и под стеклом лежит постер. Это `<img>`, тот же дешёвый путь.
Живое видео включается только при воспроизведении и только пока кнопка видна.

### 3.2 Геометрия без чтения раскладки на каждом кадре

- По `ResizeObserver` (на медиа и на host) и на `load`/`resize` один раз считаем **прямоугольники в
  координатах страницы**: `rect + scrollX/Y`. На каждом кадре читаем только `scrollY` (audit G6,
  performance §4.2).
- Для фиксированного стекла его прямоугольник постоянен во вьюпорте, для `sync: content` постоянен
  на странице.
- `object-fit: cover`/`contain` и `object-position` переводим в обрезку текстуры: для cover масштаб
  `s = max(W/iw, H/ih)`, видимая часть картинки `(W/s, H/s)` со сдвигом по `object-position`. Uniform
  `uMediaRect` (страница → UV) пересчитывается только на ресайзе.
- **Окклюдеры.** Прямоугольники `data-glass-occluder` (до 8 штук на медиа, `vec4[8]`) тоже кэшируются.
  Для сайт-пример это `.hero__panel`: она налезает на фото на 152 px, и в текстуре её нет. Без окклюдеров
  шапка, проезжая над плашкой, «показывала бы фото сквозь текст». Скругление окклюдера учитываем SDF
  скруглённого прямоугольника, как у самого стекла.

### 3.3 Маска покрытия (то, что переключает «по содержимому»)

В шейдере для каждого пикселя стекла:

```
cover = smoothstep(-1, 1, -sdBox(pPage - media))   // пиксель над медиа
      * Π (1 - smoothstep(-1, 1, -sdRoundBox(pPage - occluder_i)))   // и не под окклюдером
alpha = shape(p) * cover
```

Где `cover = 0`, canvas прозрачен, и видно матовый слой под ним. В JS та же геометрия даёт **долю
покрытия** стекла (0…1, по прямоугольникам, без пикселей). По ней решается режим (раздел 5).

Для честности у края медиа: смещённая выборка не должна читать «за краем» картинки. UV зажимаем в
`uMediaRect` (`CLAMP_TO_EDGE` плюс `clamp` по обрезке cover), а у самого края медиа сила изгиба
плавно гаснет на ширине `rim`. Это тот же приём, что «запас области» в нашем SVG-фильтре, только без
лишних пикселей.

## 4. Как считается картинка в жидком режиме

Один полноэкранный (по canvas) треугольник, один фрагментный шейдер GLSL ES 3.0. Формулы — из
graphics.md, источники там: SDF по [Inigo Quilez](https://iquilezles.org/articles/distfunctions2d/),
профиль кромки по [kube.io](https://kube.io/blog/liquid-glass-css-svg/), сквиркл и Шлик по
[Charles Grassi](https://charlesgrassi.dev/blog/apple-liquid-glass/), спектральная дисперсия по
[m2-md](https://github.com/m2-md/liquid-glass-refraction-shader) (MIT).

### 4.1 Преломление

1. `d = sdSquircleBox(p, halfSize, radius)`: расстояние до края со знаком, d < 0 внутри.
2. `x = clamp(-d / rim, 0, 1)`: доля кромки (0 у края, 1 там, где начинается плоская середина).
3. Профиль высоты `h(x) = (1 − (1 − x)^4)^(1/4)`, производная `h'(x)` аналитически.
4. Нормаль: `g = normalize(∇d)` (направление наружу, градиент SDF аналитически или по `dFdx/dFdy`),
   `n = normalize(vec3(-g · h'(x) · k, 1))`.
5. Сдвиг по Снеллиусу: `r = refract(vec3(0,0,-1), n, 1/ior)`, `off = r.xy / -r.z · thickness`.
   В плоской середине `n = (0,0,1)` и сдвиг ровно 0. Это режим Pixel Normal Offset
   ([Epic](https://dev.epicgames.com/documentation/unreal-engine/refraction-using-pixel-normal-offset-in-unreal-engine)):
   середина чистая, гнётся только кромка, как у Apple (apple.md §1).
6. Перевод `pPage + off` в UV текстуры через `uMediaRect`, `clamp` по краю медиа.

Аналитический профиль дешевле и точнее Собеля по размытой маске: ничего не пересчитывается при
прокрутке, профиль можно менять параметром.

### 4.2 Аберрация

`N` выборок вдоль одного и того же сдвига: `uv_i = uv(pPage + off · (1 + spread · (w_i − ½)))`,
`w_i = i/(N−1)`, у каждой выборки свой спектральный вес (сумма весов = белый). N = 5 на Mac,
3 на телефоне. По замерам m2-md 1/3/8 выборок стоят 0,131/0,164/0,217 мс на M2 Pro при 960×540
([README](https://github.com/m2-md/liquid-glass-refraction-shader/blob/main/README.md)) [ист., Chrome].
В середине стекла `off = 0`, и все выборки совпадают: аберрация автоматически живёт только у кромки.
Это ровно то, что у нас делали три feDisplacementMap, только почти даром.

### 4.3 Размытие, насыщение, тон

- `textureLod(tex, uv, lod)`, `lod = log2(blur · texScale)`. Мипмапы строятся один раз на текстуру.
  Для лёгкого размытия Liquid Glass (1–2 px) этого хватает, отдельный проход размытия не нужен.
- Насыщение `mix(luma, col, saturate)`, заливка тоном `mix(col, toneColor, tint)`. Тон берётся из
  `data-glass-tone` (заранее в build.py, audit G7) или считается один раз на текстуру: `drawImage` в
  canvas 8×8 и среднее (не `readPixels` из WebGL, чтобы не останавливать конвейер).
- Для варианта Clear над фото (apple.md §6) локальное затемнение до 35 % под надписями — это CSS
  (`radial-gradient` в `.lg-rim::after`), а не шейдер. Оно нужно и в матовом режиме.

### 4.4 Блик и кромка

Делятся на две части, и это главное для бесшовного переключения:

- **CSS, всегда (оба режима):** `.lg-rim::before` — рамка 1–1,5 px с
  `linear-gradient(var(--lg-light), rgba(255,255,255,.6), transparent 40% 60%, rgba(255,255,255,.25))`,
  вырезанная `mask-composite: exclude` (`-webkit-mask-composite: xor`) [Safari ?: exclude на
  псевдоэлементе]. Запасной вариант без маски: три `inset box-shadow` (audit C6, уже работает на сайте).
  Направление света `--lg-light` — `@property` типа `<angle>`, двигается от курсора на десктопе.
  При «Уменьшить движение» не двигается.
- **Шейдер, только в жидком режиме:** Френель по Шлику `F = 0.04 + 0.96 · (1 − n.z)^5` слегка
  высветляет полосу кромки изнутри, а направленный блик `pow(max(dot(n.xy, L), 0), 24) · spec` даёт
  яркую дугу сверху-слева и тусклую снизу-справа. Сила блика в шейдере подобрана так, чтобы вместе с
  CSS-рамкой он не пересвечивал. При уходе в матовое он гаснет вместе с canvas, а CSS-рамка остаётся.

### 4.5 Тень

`box-shadow` на host: `0 8px 24px rgba(0,0,0,calc(var(--lg-sh)·.35)), 0 1px 3px rgba(0,0,0,calc(var(--lg-sh)·.2))`.
`--lg-sh` зависит от того, что под стеклом: над медиа полная сила, над белой страницей половина
(Apple: над текстом тень сильнее, над светлым фоном слабее, apple.md §5). Меняется через `transition`
вместе с режимом. В фильтр и в шейдер тень не входит, поэтому не пересчитывается при прокрутке.

### 4.6 Матовый режим

`.lg-frost { backdrop-filter: blur(var(--lg-frost-blur)) saturate(1.6); background: color-mix(…tint…) }`.
То, что сейчас на сайте (audit C8), только вынесено на дочерний слой. В Firefox на Android
`backdrop-filter` при прокрутке тормозит ([bug 1732817](https://bugzilla.mozilla.org/show_bug.cgi?id=1732817)),
поэтому там радиус 8 px, а при нехватке кадров — сплошная полупрозрачная заливка.

### 4.7 Набросок шейдера

```glsl
#version 300 es
precision highp float;
uniform sampler2D uTexA, uTexB; uniform float uMix;        // кроссфейд слайдов
uniform vec2 uSize; uniform float uRadius, uRim, uThick, uIor, uSpread, uLod, uSat, uTint, uLens;
uniform vec4 uMedia;   // прямоугольник медиа в координатах стекла (px), уже с учётом scrollY
uniform vec4 uCrop;    // обрезка object-fit: uv = uCrop.xy + (p - uMedia.xy) / uMedia.zw * uCrop.zw
uniform vec4 uOcc[8]; uniform float uOccR[8]; uniform int uOccN;
uniform vec3 uTone; uniform vec2 uLight; uniform float uSpec;
in vec2 vP; out vec4 o;                                   // vP: px от центра стекла

float sdSq(vec2 p, vec2 b, float r){ vec2 q = abs(p) - b + r; vec2 m = max(q, 0.);
  return pow(dot(m*m, m*m), .25) + min(max(q.x, q.y), 0.) - r; }   // сквиркл, норма L4
vec3 samp(vec2 p){ vec2 uv = uCrop.xy + clamp((p - uMedia.xy) / uMedia.zw, 0., 1.) * uCrop.zw;
  return mix(textureLod(uTexA, uv, uLod).rgb, textureLod(uTexB, uv, uLod).rgb, uMix); }

void main(){
  float d = sdSq(vP, uSize*.5, uRadius);
  float shape = clamp(.5 - d, 0., 1.);                                  // сглаженный край, 1 px
  float x = clamp(-d / uRim, 0., 1.);
  float h1 = pow(1. - x, 3.) * pow(1. - pow(1. - x, 4.), -.75);         // h'(x) для сквиркла
  vec2 g = normalize(vec2(dFdx(d), dFdy(d)) + 1e-6);
  vec3 n = normalize(vec3(-g * min(h1, 8.) * uLens, 1.));               // uLens 0→1: «проявление»;
  // знак нормали и uThick вместе задают, тянется ли картинка к центру или наружу: подобрать по решётке
  vec3 r = refract(vec3(0, 0, -1), n, 1. / uIor);
  vec2 off = r.xy / -r.z * uThick;
  vec3 c = vec3(0); vec3 wsum = vec3(0);
  for (int i = 0; i < SAMPLES; i++) {                                   // SAMPLES: 3 или 5, при компиляции
    float w = float(i) / float(SAMPLES - 1);
    vec3 sw = clamp(vec3(1. - 2.*w, 1. - abs(2.*w - 1.), 2.*w - 1.) + .2, 0., 1.);
    c += sw * samp(vP + off * (1. + uSpread * (w - .5))); wsum += sw; }
  c /= wsum;
  float l = dot(c, vec3(.2126, .7152, .0722));
  c = mix(vec3(l), c, uSat); c = mix(c, uTone, uTint);
  float F = .04 + .96 * pow(1. - n.z, 5.);
  c += F * .35 + uSpec * pow(max(dot(-g, uLight), 0.), 24.) * (1. - x);
  float cover = 1.;  /* × маска медиа и окклюдеров, см. §3.3 */
  float a = shape * cover;
  o = vec4(c * a, a);                                                   // premultiplied
}
```

Это набросок для оценки объёма (около 60 строк). Проверять надо в лаборатории, а не по этому тексту.

## 5. Переключение на лету

### 5.1 Состояния

У каждого стекла свой автомат: `solid` ← → `frost` ← → `liquid`.

| Условие | Режим |
|---|---|
| `prefers-reduced-transparency: reduce`, `prefers-contrast: more`, `forced-colors: active`, `?glass=off`, ручной выключатель сайта | `solid`: непрозрачная плашка, рамка `currentColor` при `contrast: more` |
| нет WebGL2 (или он программный, `failIfMajorPerformanceCaveat`), контекст потерян, бюджет кадра превышен | `frost` |
| доля покрытия медиа < 0,05 | `frost` (над текстом и интерфейсом) |
| фиксированное стекло и скорость прокрутки > `fastScroll` | `frost` до `scrollend` (или 150 мс без `scroll`) |
| стекло вне экрана, вкладка скрыта | ничего не рисуем, контекст можно отдать |
| иначе | `liquid` |

Гистерезис: вход в жидкое при покрытии > 0,05, выход < 0,02; по скорости вход в матовое > 600 px/с,
возврат при `scrollend` ([Safari 26.2+](https://www.infoq.com/news/2026/04/safari-scrollend-support) [ист.])
или < 200 px/с в течение 120 мс. Иначе стекло мигает на границе фото.

### 5.2 Как выглядит переход

- `liquid → frost`: canvas `opacity 1 → 0` за 160 мс (композитор). CSS-кромка и блик на месте.
- `frost → liquid`: canvas `opacity 0 → 1` за 160 мс и одновременно uniform `uLens 0 → 1` за 250 мс.
  Картинка под стеклом сначала ровная, потом «натекает» изгиб у кромки. Apple так и показывает
  появление стекла: нарастанием lensing, а не прозрачностью ([WWDC25 219](https://developer.apple.com/videos/play/wwdc2025/219/), apple.md §1).
- Частичное покрытие (шапка над краем фото или над `.hero__panel`) переключением не считается: оба
  режима видны одновременно, граница плавная по маске (§3.3).
- «Уменьшить движение»: все переходы мгновенные, `uLens` сразу 1, слайды без кроссфейда.

### 5.3 Прокрутка: два способа синхронизации

**`sync: content`** — стекло и медиа едут вместе (кнопки ▶, подписи на фото, карточки).
Их взаимное положение постоянно, поэтому кадр рисуется **один раз** (и при смене слайда или кадра
видео). При прокрутке JS не делает ничего, canvas едет с композитором. Отставания нет в принципе.
Это самый частый случай на сайте и самый дешёвый.

**`sync: viewport`** — фиксированное стекло над прокручиваемым медиа (шапка). Перерисовка нужна на
каждом кадре прокрутки, пока под шапкой есть медиа. Кадр дешёвый, но JS узнаёт `scrollY` на кадр позже
композитора ([joyco](https://hub.joyco.studio/logs/08-webgl-scroll-sync), [Lusion, MIT](https://github.com/lusionltd/WebGL-Scroll-Sync)).
Отставание ≈ скорость × 16,7 мс: 300 px/с дают 5 px, 2000 px/с дают 33 px [оценка]. Что делаем:
1. На медленной прокрутке (< 600 px/с) рисуем жидкое и **экстраполируем** `scrollY` на полкадра вперёд
   по скорости (сглаженной по 3 кадрам). Ошибка остаётся только на разгоне и торможении. Насколько
   это помогает в Safari, неизвестно [Safari ?].
2. На быстрой прокрутке уходим в матовое (§5.1). `backdrop-filter` композитор считает синхронно с
   прокруткой, и глаз на такой скорости изгиба всё равно не разглядит (performance §5.4).
3. Вариант для A/B: «привязка к медиа» в духе Lusion. Canvas кладётся внутрь медиа (absolute), едет с
   композитором и каждый кадр сдвигается JS-ом под шапку. Тогда картинка в линзе всегда совпадает с
   фото вокруг, а на кадр отстаёт уже сама форма стекла относительно текста шапки. Какой из двух
   рассинхронов заметнее, решит только запись экрана в настоящем Safari.
4. JS-прокрутку (Lenis и т. п.) не берём: она ломает нативную прокрутку на iPhone (graphics.md §2.2в).

Где лежит медиа, известно заранее, поэтому `IntersectionObserver` на медиа с
`rootMargin: -<высота шапки>px` полностью снимает слушатель `scroll`, как только фото ушло из-под
шапки (audit G6, performance §5.5). На остальной странице шапка просто матовая и ничего не считает.

### 5.4 Регулятор качества

- Уровни: `L2` (5 выборок, DPR до 2), `L1` (3 выборки, DPR 1,5–2, без шейдерного блика), `frost`, `solid`.
- Старт: Mac / десктоп — `L2`, телефон (`pointer: coarse`) — `L1`.
- Во время жидкого режима считаем интервалы rAF. Если p95 > 1,5 × период обновления две секунды
  подряд, опускаемся на уровень. На уровень вверх не поднимаемся до перезагрузки, решение кладём в
  `sessionStorage` (обёрнуто в try/catch, без него просто начинаем с уровня по умолчанию).
- DPR canvas ограничен 2 (на iPhone с DPR 3 это минус 55 % пикселей). Стеклу с размытием и
  изгибом третья плотность не нужна.

### 5.5 Контексты WebGL

- v1: по контексту на **видимое** жидкое стекло, не больше `maxContexts = 4`. Создаём лениво при входе
  в зону видимости (`rootMargin: 200px`), освобождаем `WEBGL_lose_context` + `canvas.width = 0` при
  выходе (память canvas на iOS ограничена, [pqina](https://pqina.nl/blog/total-canvas-memory-use-exceeds-the-maximum-limit/)).
  Лимит браузера около 16 контекстов на страницу (performance §5.3).
  Между контекстами текстуры не делятся, поэтому в v1 каждое стекло загружает картинку само (768 px,
  около 1–2 мс [оценка]). Для 1 шапки + 2–3 кнопок это нормально.
- v2 (если стёкол станет много): один `OffscreenCanvas` с WebGL2 на главном потоке, каждое стекло
  рисуется в него по очереди и отдаётся через `transferToImageBitmap()` в `bitmaprenderer`-canvas стекла
  ([MDN: один OffscreenCanvas → любое число ImageBitmapRenderingContext](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/transferToImageBitmap)).
  OffscreenCanvas WebGL в Safari есть с 17, но с багами (browsers.md) [Safari ?].
- `webglcontextlost` → режим `frost`, `webglcontextrestored` → заново текстуры и программа.

### 5.6 Почему не SVG и не WebGPU

- SVG-фильтр в гибриде не нужен: над медиа WebGL лучше по всем трём осям (скорость, одинаковый вид,
  поддержка), а над DOM у нас по замыслу матовое. Это снимает расхождение «в Chrome выглядит иначе,
  чем в Safari»: шейдер один на всех.
- WebGPU даёт выигрыш только при compute-проходах. Для одного квадрата узкое место — заливка пикселей,
  а инициализация асинхронная и кода больше (graphics.md §2.3). Оставляем WebGL2.
- Исключение, которое можно включить флагом `domRefraction: 'chromium'`: в Chromium
  `backdrop-filter: url(#svg)` с готовой картой через `feImage` считается на GPU и честно гнёт DOM. Это
  выходит за рамки угла «по содержимому» и даёт разный вид в разных браузерах. По умолчанию выключено.

## 7. Ожидаемая скорость

Всё ниже — **[оценка]**, кроме строк с пометкой. Замер нужен до встраивания (раздел 9).

| Что | Mac (Apple Silicon, DPR 2) | iPhone (DPR 3 → canvas 2) |
|---|---|---|
| Пикселей шапки в canvas | 1100×60 × 4 ≈ 264 тыс. | 361×56 × 4 ≈ 81 тыс. |
| Выборок текстуры на пиксель | 5 | 3 |

| Кнопки и подписи при прокрутке | 0 (рисуются один раз) | 0 |
| Смена слайда | `decode()` вне главного потока + `texImage2D` 768×512 + мипмапы ≈ 1–3 мс, один раз; кроссфейд 900 мс = 54 дешёвых кадра шейдера | ≈ 2–5 мс один раз |
| Видео под ▶ (при воспроизведении) | загрузка кадра 640×360 ≈ 1–2 мс × 30 Гц | неизвестно, у WebKit история регрессий ×20 ([236699](https://bugs.webkit.org/show_bug.cgi?id=236699)) [Safari ?] |
| Матовое `backdrop-filter` | GPU, на сайте уже без лагов [S27] | GPU [ист.] |
| Память | текстура 768×512 ≈ 1,5 МБ + мипы 0,5 МБ, ×2 на кроссфейд; canvas шапки ≈ 1 МБ × 2–3 буфера | то же, canvas ≈ 0,3 МБ × 2–3 |
| Вес | JS ≈ 8–10 КБ gzip, CSS ≈ 1,5 КБ | то же |

Для сравнения, сейчас (SVG по копии) [S27]: Safari Mac 60 fps, худший кадр 33 мс; на iPhone стекло
выключено, потому что было «очень плохо». По коду WebKit это ~17 программных проходов по ~0,5–0,8 Мп
на каждом кадре прокрутки (fresh.md §1.2, audit). Гибрид переносит эту работу на видеокарту и
сокращает её примерно на два порядка. Если оценки подтвердятся, бюджет кадра (16,7 мс при 60 Гц)
будет занят шейдером меньше чем на 5 %, и даже iPhone получит жидкую шапку.

Цели («годится») — как в performance §6.5: Mac p95 ≤ 16,7 мс, худший ≤ 25 мс; iPhone p95 ≤ 17 мс,
худший ≤ 33 мс; смена слайда без кадров > 33 мс; отставание линзы p95 ≤ 1 кадра на медленной прокрутке.

## 8. Риски

| # | Риск | Вероятность / вред | Что делаем |
|---|---|---|---|
| R1 | Картинка в линзе шапки отстаёт от фото вокруг на кадр прокрутки | высокая / средний | матовое на быстрой прокрутке, экстраполяция `scrollY`, A/B «привязка к медиа» (§5.3). Мерить записью экрана 120/240 fps в настоящем Safari первым делом |
| R2 | Текстура не знает про DOM поверх медиа (плашка, подпись, бейдж) — в линзе «исчезает текст» | высокая без окклюдеров / высокий | `data-glass-occluder`, маска в шейдере; в debug-HUD подсвечивать окклюдеры. Ловушка: забытый окклюдер. Автопоиск: позиционированные потомки медиа-контейнера считаются окклюдерами по умолчанию |
| R3 | Анимации CSS над медиа (Ken Burns, параллакс фото, `transform` у img) — текстура их не повторяет | средняя / средний | плагин читает `transform` медиа только на ресайзе; анимированное медиа помечать `data-glass-media-animated` → стекло над ним матовое. У сайт-пример фото статичное |
| R4 | rVFC + WebGL в WebKit теряет контексты (сообщение по Playwright) | неизвестно / средний | для WebKit опрос кадров в rAF, постер по умолчанию, живое видео только при воспроизведении; проверить на iPhone |
| R5 | `texImage2D(video)` в Safari медленный (история регрессий) | средняя / средний | 30 Гц потолок, 640 px, регулятор качества; на iPhone — постер |
| R6 | «Уменьшить прозрачность» в Safari не распознать из веба | точно / средний (доступность) | выключатель «Без прозрачности» в подвале сайта, `solid` по нему; честно описать это в отчёте владелец сайтау |
| R7 | Ложное срабатывание `pointer: coarse`/скорости, мигание режимов на границе фото | средняя / низкий | гистерезис (§5.1), переходы 160 мс |

| R9 | Разный вид шейдера и матового режима (переход «бросается в глаза») | средняя / средний | общие тон, насыщение и кромка в CSS; шейдерное размытие и `frostBlur` подбирать рядом в лаборатории |

## 9. Что проверить в настоящем Safari до кода плагина (по порядку)

1. **Прототип шапки** (одна страница в `glass-rnd/`, одна картинка, шейдер §4.7, canvas в
   фиксированной капсуле). Запись экрана 120 fps при медленной и быстрой прокрутке трекпадом:
   насколько видно отставание (R1). Сразу же — вариант «привязка к медиа» (§5.3 п. 3).
2. Тот же прототип на iPhone: зонд кадров (performance §6.2), Web Inspector по кабелю, нагрев за минуту.
3. Переход `frost ↔ liquid` с `uLens`: нет ли вспышки или скачка кромки.
4. Кнопка ▶ над постером и над играющим видео на iPhone (R4, R5).
5. Окклюдер `.hero__panel`: шапка над стыком фото и плашки.
6. `mask-composite: exclude`, `@property` для угла блика, `prefers-contrast: more` в Safari.
7. Цвет в линзе против фото рядом на P3-картинке (R10).

Playwright-WebKit для этого не годится [S27]: только настоящий Safari и настоящий iPhone.

## 10. Чем гибрид отличается от того, что есть сейчас

| | Сейчас (`glass.js`) | Гибрид |
|---|---|---|
| Картинка за стеклом | копия `<img>` в DOM под SVG-фильтром | текстура WebGL из того же `<img>` (маленький вариант) |
| Изгиб | Собель по размытой маске, каждый кадр, CPU в Safari | аналитический SDF + Снеллиус, GPU |
| Аберрация | 3 × feDisplacementMap | 3–5 выборок в том же проходе |
| Над текстом | матовое (уже так) | матовое, решает маска покрытия, переход плавный |
| Кромка, блик, тень | CSS `::before` + inset-тени | то же, плюс шейдерный Френель в жидком режиме |
| Телефоны | стекло выключено | жидкое L1 с регулятором |
| Смена слайда | новые `<img>` в линзе + 900 мс opacity под фильтром | две текстуры, `mix` в шейдере |
| Safari-грабли | feImage, sRGB, userSpaceOnUse, translate3d, кэш id | не касаются (SVG нет) |
| Одинаковый вид Chrome/Safari | нет | да (один шейдер) |

Что переносим из нынешнего кода (audit, «Что переносить»): CSS-слой кромки, тон с гистерезисом
0,42/0,58 (как источник `data-glass-tone`), идею кроссфейда, лабораторию как стенд (с fps и худшим
кадром). Не переносим: SVG-генератор фильтра (остаётся в лаборатории для сравнения), клей сайта
(`.nav__row`, `.hero__*`, событие `slide`), `localStorage` на живых страницах.
